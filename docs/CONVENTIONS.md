# Repository conventions

The rules every pattern, test and document in this repository follows. They keep the four
implementations of each pattern comparable and the lessons easy to navigate.

## Principles

- **One example, four languages.** Each pattern solves the same practical problem in C#, TypeScript
  (with a React demo), Python and Go, using the same names (only the casing convention changes).
- **Same behaviour, proven.** Every console program prints exactly the pattern's
  `expected_output.txt`; `scripts/verify.sh` compares all four.
- **Idiomatic, not literal.** Each language uses its own idioms (C# records and primary constructors,
  TypeScript structural types, Python dataclasses and `Protocol`, Go small interfaces and embedding).
  The lesson's *Language notes* explain where they differ.
- **Standard library only** in the examples (React for the demos). Tooling and test dependencies are
  allowed.
- **Deterministic.** No randomness, real clocks, real network calls or racy threads, in examples or
  tests. Slow or remote work is simulated and printed (`[remote] fetching doc-1`).
- **English only** in code, comments, documentation, commits and pull requests.

## Layout per pattern

```text
patterns/<category>/<pattern>/          category: creational | structural | behavioral
├── README.md                           the lesson (docs/PATTERN_TEMPLATE.md)
├── expected_output.txt                 what every console program prints
├── csharp/<Pattern>.csproj, *.cs       namespace DesignPatterns.<Pattern>
├── typescript/<core>.ts                framework-agnostic core
├── typescript/main.ts                  console demo
├── typescript/<Pattern>Demo.tsx        React demo, default export, discovered by the playground
├── typescript/*.test.ts(x)             Vitest (+ Testing Library for the demo)
├── python/main.py, python/test_main.py
└── go/main.go, go/main_test.go         package main
tests/csharp/DesignPatterns.Tests/<Category>/<Pattern>Tests.cs
```

- Folder names are kebab-case (`chain-of-responsibility`); C# project and class names are PascalCase.
- Every participant has a doc comment naming its role in the pattern (`Concrete Strategy: ...`).
- The first output line is `=== <Pattern> Pattern: <example title> ===`.

## Output formatting

The four programs must print byte-identical text, so formatting is explicit everywhere:

| What | C# | TypeScript | Python | Go |
| --- | --- | --- | --- | --- |
| Money / decimals | `{x:0.00}` | `x.toFixed(2)` | `f"{x:.2f}"` | `%.2f` or integer cents |
| Left-aligned column | `{x,-16}` | `x.padEnd(16)` | `f"{x:<16}"` | `%-16s` |
| Booleans | `true` / `false` (lowercase) | `String(b)` | `str(b).lower()` | `%t` |

## Tests

- Test the pattern's **roles and guarantees** (the same instance, a deep clone, undo restores the
  state, an invalid transition is rejected...), not only the happy path.
- Equivalent cases in every language, named the language's way: `Method_does_something` (xUnit),
  `test_does_something` (pytest), `TestDoesSomething` (Go), `it("does something")` (Vitest).
- Python and Go also check that the demo prints `expected_output.txt`.
- C# tests that capture the console use `ConsoleCapture` and belong to the `Console` collection.
- Python tests load the sibling `main.py` through the `example` fixture in `conftest.py`.

## Documentation

- Lessons follow [PATTERN_TEMPLATE.md](PATTERN_TEMPLATE.md) section by section.
- The *Expected output* block is generated by `python3 scripts/sync_readme.py`; never edit it by hand.
- Mermaid class diagrams only; use `~T~` for generics.
- *Real-world usages* list only well-known, verifiable APIs.
- Relative links only, checked by `python3 scripts/check_links.py`.

## Quality gates

`make all` runs exactly what CI runs:

- **C#:** locked NuGet restore, .NET analyzers `latest-recommended`, code style enforced in the build,
  warnings as errors, xUnit.
- **TypeScript + React:** `npm audit`, strict TypeScript, Vitest + Testing Library, playground build.
- **Python:** Ruff (lint + format), mypy `--strict`, pytest with branch coverage, on 3.10 and 3.13.
- **Go:** `gofmt`, `go vet`, `go test -race`.
- **Examples and docs:** `scripts/verify.sh`, `scripts/sync_readme.py --check`, `scripts/check_links.py`.

Shell scripts are invoked as `bash scripts/<name>.sh`, never directly, so they work without the
executable bit.

## Commits

The history follows [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/):
`feat(observer): ...`, `fix(go): ...`, `test(builder): ...`, `docs(readme): ...`, `build: ...`,
`ci: ...`, `chore: ...`. Pull request titles are validated in CI, and
[release-please](https://github.com/googleapis/release-please) builds `CHANGELOG.md` and the releases
from them. Commits on `main` must be signed.
